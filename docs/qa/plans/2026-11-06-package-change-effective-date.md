# OilStation — แผนตรวจสอบการเปลี่ยนแพ็กเกจและวันเริ่มแพ็กเกจใหม่

**คำขอเพิ่มเติม 6 พฤศจิกายน 2026.** ขอบเขตต้องครอบคลุมทั้ง **การเปลี่ยนแพ็กเกจเดิมเป็นแพ็กเกจใหม่** (รายเดือน ↔ รายปี และแบบรวมโมดูล), **วันที่เริ่มมีผล**, และความถูกต้องของ Billing/สิทธิ์/ใบแจ้งหนี้ โดยไม่ใช้เงินหรือสร้างธุรกรรมจริงในการทดสอบ QA.

## สิ่งที่ตรวจพบจริง (ยังไม่ใช่ PASS)

- Production `public.station_subscriptions` เก็บ `plan_id, starts_at, current_period_end, status` แต่ไม่มีคำขอเปลี่ยนแพ็กเกจล่วงหน้าหรือวันที่เริ่มของแพ็กเกจถัดไป
- Production RPC `station_select_saas_plan` ปฏิเสธการเลือกแพ็กเกจใหม่ทันทีเมื่อสถานีมีสถานะ `trialing`, `active`, `grace` หรือ `overdue`
- `src/client/station-plan-choice.js` เป็น UI สำหรับ **เลือกแพ็กเกจครั้งแรกก่อนจ่าย** ไม่ใช่หน้าจอเปลี่ยนแพ็กเกจที่มีอยู่ และไม่มีช่องวันที่เริ่มใหม่
- ปัจจุบันมี subscription สถานี QA ในสถานะ `trialing` หนึ่งรายการ รอบเดิม `2026-11-01T00:00:00Z` ถึง `2026-12-01T00:00:00Z` (เวลาไทยวันที่ 1 ธันวาคม **07:00 น.**) **ห้ามตีความวันที่ 1 ธันวาคม 00:00 น. เป็นเวลาเริ่มแพ็กเกจใหม่โดยไม่แปลงเขตเวลา** เพราะจะทับซ้อน 7 ชั่วโมง
- `src/domain/subscription-renewal.mjs` มีการคำนวณรอบถัดไปและ revision price เป็น pure preview แล้ว แต่ **ไม่ได้ persist การเปลี่ยนแพ็กเกจ/อนุมัติเงิน/เริ่มสิทธิ์** จึงไม่ใช่หลักฐานว่าเปลี่ยนแพ็กเกจจริงได้

## นโยบายปลอดภัยที่เสนอเป็นเกณฑ์ QA

1. **ค่าเริ่มต้น:** เปลี่ยนที่ `current_period_end` ของรอบเดิม (end-exclusive); ไม่มีการคิดเงินส่วนที่เหลือซ้ำอัตโนมัติ; ให้แสดงวันที่และเวลาไทยให้เจ้าของปั๊มเห็น
2. **อนาคต:** เลือกวันเริ่มที่ช้ากว่ารอบปัจจุบันได้เมื่อออกแบบการต่ออายุแพ็กเกจเดิมระหว่างรอไว้ครบแล้ว; ไม่ให้เกิดช่วงว่างของสิทธิ์หรือบิลสองฉบับสำหรับช่วงเดียวกัน
3. **ทันที/ระหว่างรอบ:** ต้องมีนโยบายคิดเงินเพิ่มหรือคืนเงิน/เครดิตคงเหลือและข้อความยืนยันที่ชัดเจน; หากยังไม่รองรับให้ปิดการเลือกและไม่สร้างธุรกรรม
4. **รายเดือน ↔ รายปี:** ตรวจรอบใหม่โดยนับจากวันเริ่มมีผลจริง รวมวันที่ 28/29 กุมภาพันธ์, สิ้นเดือน, ข้ามปี และการคงวันรอบอ้างอิง
5. **การเงิน:** ราคาแพ็กเกจ/VAT/ส่วนลด QR ณ วันเริ่มใหม่มี snapshot ของตัวเอง; ไม่เขียนทับใบแจ้งหนี้เดิม; การเรียกเก็บเงินและค่าคอมมิชชั่นไม่ซ้ำในกรณี submit/retry/webhook ซ้ำ
6. **สิทธิ์และ Audit:** เจ้าของปั๊มที่มีสิทธิ์เท่านั้นจึงจะเปลี่ยน/ยกเลิกได้; จดรายการเก่า ใหม่ วันที่เริ่ม ผู้กระทำ เหตุผล และการแก้ไขคำขอซ้ำให้ตรวจสอบได้

## 12 เคสใหม่ — ทดสอบ 2 รอบ รอบละ 6 เคส

| รอบ A | กรณีทดสอบ |
|---|---|
| PC-01 | รายเดือน → รายปี เริ่มวันสิ้นรอบปัจจุบัน |
| PC-02 | รายปี → รายเดือน โดยไม่มีสิทธิ์ซ้อน/หาย |
| PC-03 | วันเริ่มแพ็กเกจใหม่ในอนาคต + Asia/Bangkok |
| PC-04 | เปลี่ยนทันทีพร้อม prorate / credit (หรือป้องกันถ้ายังไม่รองรับ) |
| PC-05 | วันที่ไม่ถูกต้อง ย้อนหลัง ก่อนสิ้นรอบ และชนรอบ |
| PC-06 | แพ็กเกจเดิม/ไม่ active/ไม่ครอบคลุมโมดูลถูกปฏิเสธ |

| รอบ B | กรณีทดสอบ |
|---|---|
| PC-07 | Request ID ซ้ำ/พร้อมกัน ไม่สร้างคำขอ/บิลเพิ่ม |
| PC-08 | ยกเลิกหรือเลื่อนวันที่คำขอเปลี่ยนแพ็กเกจก่อนเริ่ม |
| PC-09 | ราคาปรับใหม่ VAT/2% ส่วนลดตามวันเริ่ม และ invoice snapshot |
| PC-10 | Owner สถานีอื่น / Cashier / Sales ไม่สามารถเปลี่ยนได้ |
| PC-11 | เปิดสิทธิ์ใหม่ตรงเวลาและปิดเดิมแบบ atomic ไม่คิดซ้ำ |
| PC-12 | เปลี่ยนหนึ่งสถานีในบิลรวม ไม่กระทบอีกสถานีหรือคอมมิชชั่น |

## การพัฒนาและการปิด UAT ที่ต้องทำก่อนนับว่า PASS

- ออกแบบตาราง `station_plan_change_requests` สำหรับ scheduled change, `requested_start` เป็น `timestamptz`, `requested_by`, สถานะ `pending/applied/cancelled`, idempotency key, price snapshot และ audit ที่ไม่ลบประวัติเดิม
- เพิ่ม authenticated read-only endpoint แสดง **แพ็กเกจปัจจุบัน/วันสิ้นรอบ/คำขอเปลี่ยนที่รอ** และ mutation endpoint เฉพาะเจ้าของสถานีสำหรับ schedule/cancel; ตรวจ RLS และ SQL locking ก่อนเปิดใช้งาน
- เพิ่ม UI เลือกแพ็กเกจใหม่ + วันเริ่ม + สรุปค่าใช้จ่าย; แยกชัดจากการเลือกครั้งแรก; ปรับ Layout mobile-first ให้เข้าใจสถานะก่อน/หลัง
- เพิ่มการประมวลผลในรอบจ่ายจริงเมื่อ release gate อนุมัติแล้ว; ไม่เริ่มแพ็กเกจล่วงหน้าและไม่สร้างใบแจ้งหนี้ซ้ำ
- เขียน unit + rollback-only SQL concurrency + Browser E2E ของ **PC-01 ถึง PC-12** พร้อมเทียบ Supabase pre/post, จึงเปลี่ยน status เป็น PASS ทีละเคส
- **ปัจจุบันทุก PC-01–PC-12 = BLOCKED_IMPLEMENTATION; ไม่มีการทดสอบเปลี่ยนแพ็กเกจจริงใดผ่าน**. ไม่ถือเป็นผลปล่อย Full Production.
